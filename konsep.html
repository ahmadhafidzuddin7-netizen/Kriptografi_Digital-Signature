What is a
Digital Signature?

Digital Signature atau tanda tangan digital adalah mekanisme kriptografi yang digunakan untuk memeriksa apakah sebuah pesan masih asli dan apakah tanda tangannya cocok dengan kunci publik yang digunakan untuk memeriksanya.

Misalnya, seseorang mengirimkan dokumen digital kepada orang lain. Penerima ingin memastikan bahwa isi dokumen tidak berubah selama proses pengiriman dan tanda tangan digitalnya sesuai dengan kunci publik yang diberikan.

Untuk melakukan pemeriksaan tersebut, Digital Signature menggunakan dua kunci yang saling berhubungan: Private Key dan Public Key.

INTEGRITY AUTHENTICITY NON-REPUDIATION*
*Non-repudiation bergantung pada pengelolaan kunci, pembuktian identitas, dan kerangka hukum atau kepercayaan yang berlaku.

Digital Signature Algorithms

Ada beberapa algoritma yang dapat digunakan untuk membuat tanda tangan digital. Masing-masing menggunakan pendekatan matematika yang berbeda.

R
FACTORISATION

RSA-PSS

RSA-PSS adalah skema tanda tangan digital yang menggunakan algoritma RSA. Keamanannya berkaitan dengan sulitnya memecah bilangan besar menjadi faktor-faktor prima. RSA-PSS merupakan salah satu skema yang umum direkomendasikan untuk penggunaan baru.

RSA Widely supported
D
DISCRETE LOG

DSA

DSA merupakan algoritma tanda tangan digital yang lebih lama. Keamanannya berkaitan dengan masalah matematika yang disebut logaritma diskrit. DSA bukan pilihan utama untuk sistem baru.

Legacy Signature only
E
ELLIPTIC CURVE

ECDSA

ECDSA menggunakan konsep matematika kurva eliptik untuk membuat dan memeriksa tanda tangan digital. Salah satu kelebihannya adalah ukuran kunci dapat lebih kecil dibandingkan RSA untuk tingkat keamanan yang sebanding.

Our choice ECDSA P-256
Ed
EDWARDS CURVE

EdDSA

EdDSA adalah keluarga algoritma tanda tangan digital yang menggunakan kurva Edwards. Salah satu contohnya adalah Ed25519. Algoritma ini dirancang agar proses membuat dan memeriksa tanda tangan berjalan secara efisien.

Understanding ECDSA

Program kita menggunakan ECDSA. Pada bagian ini, kita akan mengenal konsep dasar kurva eliptik dan memahami bagaimana ECDSA membuat serta memeriksa tanda tangan digital.

ECDSA

Elliptic Curve Digital Signature Algorithm

ECDSA adalah algoritma untuk membuat dan memeriksa tanda tangan digital dengan menggunakan matematika kurva eliptik. Secara sederhana, Private Key digunakan untuk membuat tanda tangan, sedangkan Public Key digunakan untuk memeriksanya.

Ilustrasi konseptual, bukan plot parameter P-256 yang sebenarnya.
01

Elliptic Curve

Kurva yang memiliki aturan matematika tertentu. Titik-titik pada kurva ini dapat digunakan dalam operasi matematika yang menjadi dasar teknologi Elliptic Curve Cryptography (ECC).

02

Generator Point (G)

Generator Point adalah titik khusus pada kurva yang digunakan sebagai titik awal dalam proses perhitungan kunci.

03

Private Key (d)

Private Key adalah sebuah angka rahasia yang hanya boleh diketahui oleh pemilik kunci. Angka ini digunakan untuk membuat tanda tangan digital.

04

Public Key (Q)

Public Key dibentuk melalui perhitungan Private Key dengan Generator Point. Kunci ini boleh dibagikan dan digunakan untuk memeriksa tanda tangan digital.

PUBLIC KEY RELATIONSHIP Q = d × G

Public Key (Q) diperoleh dengan mengalikan Private Key (d) dengan Generator Point (G) menggunakan aturan matematika kurva eliptik. Proses menghitung Public Key dari Private Key dapat dilakukan dengan mudah. Namun, mencari Private Key hanya berdasarkan Public Key merupakan masalah matematika yang sangat sulit. Inilah salah satu dasar keamanan ECC.

How ECDSA Generates a Signature

Ketika pengirim ingin menandatangani pesan, ECDSA menggunakan hasil hashing dan Private Key untuk melakukan perhitungan matematika. Hasil akhirnya berupa dua angka, yaitu r dan s, yang bersama-sama membentuk tanda tangan digital.

INPUT Message Pesan asli
→
HASHING SHA-256 Message digest (z)
→
ECDSA SIGN Private Key + nonce Operasi matematis kurva
→
OUTPUT Signature (r, s) Digital signature
COMPONENT 01 · CALCULATING r r = xR mod n

Pertama, angka sementara yang disebut nonce (k) dikalikan dengan Generator Point (G) untuk mendapatkan titik R. Nilai r kemudian diperoleh dari koordinat x titik R yang dihitung menggunakan operasi modulo n.

Dengan kata lain, nilai r berasal dari hasil perhitungan nonce pada kurva eliptik.

COMPONENT 02 · CALCULATING s s = k−1(z + rd) mod n

Nilai s dihitung menggunakan beberapa komponen: hash pesan (z), Private Key (d), nonce (k), dan nilai r yang sudah diperoleh sebelumnya.

Setelah nilai r dan s diperoleh, keduanya menjadi bagian dari tanda tangan digital.

VARIABLE EXPLANATION · SIGNING k = Nonce z = Hash pesan d = Private Key G = Generator Point R = k × G xR = Koordinat x dari titik R n = Orde Generator Point

Simbol mod menunjukkan operasi modulo, yaitu operasi untuk mendapatkan sisa pembagian. Sementara itu, k⁻¹ adalah invers perkalian dari k dalam modulo n.

Security note: Nonce (k) adalah angka sementara yang digunakan dalam proses Signing. Nilainya harus rahasia, unik, dan tidak boleh digunakan ulang secara tidak aman. Jika nonce dikelola dengan keliru, Private Key dapat terancam. Dalam program kita, pengelolaan nonce ditangani oleh Web Crypto API, sehingga tidak perlu dibuat secara manual.

How ECDSA Verifies a Signature

Setelah pesan diterima, penerima menggunakan pesan, tanda tangan (r dan s), serta Public Key untuk melakukan pemeriksaan. Tujuannya adalah memastikan apakah tanda tangan tersebut cocok dengan pesan yang diterima dan Public Key yang digunakan.

INPUT Message + (r,s) Data yang diterima
→
HASHING SHA-256 Hash pesan (z)
→
ECDSA VERIFY Public Key Perhitungan verifikasi
→
OUTPUT Valid / Invalid Hasil verifikasi
VERIFICATION EQUATIONS w = s−1 mod n u1 = zw mod n u2 = rw mod n X = u1G + u2Q r = xX mod n

Dalam proses ini, sistem menghitung nilai bantu dari tanda tangan dan hash pesan. Selanjutnya, sistem menggunakan Generator Point (G) dan Public Key (Q) untuk mendapatkan titik X. Jika nilai r hasil perhitungan sama dengan nilai r pada tanda tangan, tanda tangan dinyatakan valid.

VARIABLE EXPLANATION · VERIFICATION w = Invers dari s modulo n z = Hash pesan r, s = Komponen tanda tangan digital u₁, u₂ = Nilai bantu dalam verifikasi G = Generator Point Q = Public Key X = Titik hasil perhitungan verifikasi xX = Koordinat x dari titik X n = Orde Generator Point

Persamaan terakhir merupakan kondisi pemeriksaan. Sistem membandingkan nilai r yang dihitung dari titik X dengan nilai r yang terdapat pada tanda tangan digital.

Hal penting: proses Verification bukan proses untuk membuka atau mendekripsi tanda tangan. Public Key digunakan untuk memeriksa kecocokan tanda tangan dengan pesan. Jika pemeriksaan berhasil, tanda tangan dinyatakan valid.

Why P-256?

P-256 adalah salah satu kurva eliptik standar yang dapat digunakan bersama ECDSA. Kurva ini memiliki ukuran parameter 256 bit dan didukung oleh Web Crypto API, sehingga dapat digunakan langsung dalam program berbasis browser.

The Role of SHA-256

SHA-256 dan ECDSA memiliki fungsi yang berbeda, tetapi keduanya bekerja bersama dalam proses tanda tangan digital.

#
HASH FUNCTION

SHA-256

SHA-256 adalah fungsi hash yang mengubah data, baik pendek maupun panjang, menjadi ringkasan berukuran 256 bit. Jika isi pesan berubah, hasil hash-nya juga akan berbeda dengan kemungkinan yang sangat tinggi.

MESSAGE → 256-BIT DIGEST
≠
✎
SIGNATURE ALGORITHM

ECDSA

ECDSA menggunakan hasil hash bersama Private Key untuk membuat tanda tangan digital. Setelah itu, Public Key digunakan untuk memeriksa apakah tanda tangan tersebut cocok dengan pesan.

DIGEST + KEY → SIGNATURE
Intinya: SHA-256 bertugas membuat ringkasan pesan, sedangkan ECDSA bertugas membuat dan memeriksa tanda tangan digital. Jadi, SHA-256 bukan algoritma tanda tangan digital.
